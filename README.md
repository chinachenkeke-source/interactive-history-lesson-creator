# 🏛️ 历史交互课件制作 Skill

把历史教材做成可进入、可观察、可与人物对话的课堂课件。这个 Skill 首先帮助教师**讨论并确定一共几幕**，再推进史实核对、情境设计、视听制作和逐幕验收。

## 🧭 最重要的第一步：先讨论幕数

教师提供课文、教材截图、课标或史料后，Skill 会先提出一份具体的分幕建议：

| 需要讨论 | 应向教师说明 |
| --- | --- |
| 一共几幕 | 为什么需要这些幕，哪些事件适合合并或独立 |
| 每幕讲什么 | 时间、地点、核心事件和要解决的历史问题 |
| 怎样互动 | 学生观察什么、与谁对话、作出什么判断 |
| 顺序如何安排 | 事件发生顺序与教材叙述顺序是否一致 |

教师给出幕数及顺序的意见后，才开始制作整套课件。若教师一开始已经明确指定，直接按该意见推进。

> 示例：根据你提供的材料，我建议分为 **6 幕**：①……②……③……。其中第 3 幕侧重史料，第 5 幕适合人物对话。你希望采用这个幕数和顺序，还是合并、增补某一幕？

## 📚 完整制作过程

### 1. 核对教材与史实

明确教材版本、课次、页码和课标目标；整理关键事件、时间线、人物、概念与因果关系。把教材主干与课堂延伸分开。课堂延伸需要可靠来源，拟写对白必须标明其教学模拟性质。

### 2. 设计逐幕学习任务

每幕围绕一个历史问题。先确定学生在场景中能看到什么，再设计点击热点、局部图片、角色提问和参考解读。热点应贴近真实的画面对象，不把无关图片当作证据。

### 3. 写讲述和互动对白

场景讲述交代进入情境所需的背景。互动让学生以「你」的身份向角色提问，角色的回答回应本幕知识目标。让互动自然发生，避免把制作要求写进学生页面。

### 4. 处理历史选择

可以让学生投票、辩论或比较不同立场，但课堂选择不能改变真实历史结果。若真实程序比课堂选项复杂，需说明简化之处；先让学生思考，再揭示史实与依据。

### 5. 制作画面和声音

场景图、局部图要匹配事件与时代，情境画不冒充史实照片。讲述和角色语音要清楚自然；背景声符合地点和行动，避免持续嘶声，并提供独立静音开关。动效服务于沉浸感，也要保持画面清晰。

### 6. 做适合课堂的字幕与界面

为每段语音显示字幕，明确标出「场景讲述」「你」或角色名称，并用颜色区分。字幕优先按完整句显示，宽度随句子伸展，避免末行只剩一两个字；投影字体要足够大。字幕不能使交互卡片缩短。教师参考解读可展开，学生页面保持简洁。

### 7. 构建、核对和交付

根据用户要求输出可离线使用的课件，附源文件、素材与史实来源说明。逐幕测试所有热点、对白、选择结果、字幕、环境声、静音、返回与场景切换；检查桌面投影和手机布局。教师提出修改后，修正并重新验收相关流程。

## ✅ 交付前检查

- [ ] 幕数和场景顺序已取得教师意见。
- [ ] 时间线与教材一致；回看事件已明确提示。
- [ ] 教材主干、史料延伸和教学拟写有清楚边界。
- [ ] 每个热点的图片、文字、语音与点击目标相符。
- [ ] 学生的选择有反馈，但不会改写历史事实。
- [ ] 所有语音有清楚的讲话者字幕，环境声可单独关闭。
- [ ] 字幕、交互卡片和按钮在投影及手机上可读、可用。
- [ ] 离线课件、来源说明和源文件已交付。

## 🚀 使用方式

将本仓库中的 `SKILL.md` 放入 Codex 的技能目录，例如 `~/.codex/skills/interactive-history-lesson-creator/SKILL.md`，然后在对话中调用 `$interactive-history-lesson-creator`，并提供教材或课文。

推荐的起始请求：

> 使用 `$interactive-history-lesson-creator`，根据我提供的教材制作历史交互课件。请先和我讨论一共分几幕、每幕讲什么，等我确定后再制作。

本仓库**只包含 Skill 文档**，不包含任何课件成品、教材截图、生成图片、音频或学生数据。
